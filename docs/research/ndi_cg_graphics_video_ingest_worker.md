# Component Specification: NDI CG / Graphics Video Ingest Worker

## 1. Executive Summary & Purpose

The **NDI CG / Graphics Video Ingest Worker** is a headless microservice that discovers and receives compressed network video streams (Character Generator graphics, lower thirds, or slides) over an IP local area network using the NDI protocol.

The worker decodes the incoming stream to an uncompressed raster (retaining full 8-bit or 16-bit alpha transparency), acts as an asynchronous **Re-Timing Boundary** onto the host's SMPTE 2059-1 TAI timeline, and publishes the resulting video grains into an EBU Media eXchange Layer (MXL) discrete ring buffer in `/dev/shm`.

## 2. Technical Stack & Dependencies

* **Language:** C++20 or Rust.

* **NDI Library:** NDI Advanced or Core SDK (`libndi.so` / `libndi.dylib`) version 5.x or 6.x.

* **OS / Kernel:** Linux with POSIX shared memory enabled.

* **Clock Reference:** Linux kernel clock `CLOCK_TAI` (disciplined by `chrony` NTP).

* **Shared Memory Interprocess Communication (IPC):** EBU MXL C SDK (`libmxl`) v1.1.

## 3. Asynchronous Arrival & Retiming Boundary Architecture

```
[ Remote CG Computer (ProPresenter / vMix / CasparCG) ]
  │
  └── Generates graphics clocked to local OS CPU wall-clock
        │
        ▼ (NDI IP Packets over mDNS / Discovery Server)
┌────────────────────────────────────────────────────────────────────────┐
│ NDI Ingest Worker Process                                              │
│                                                                        │
│  1. NDI Receiver (NDIlib_recv_capture_v2)                              │
│     Pulls decoded frames from NDI SDK queue                            │
│                                                                        │
│  2. Color Space & Transparency Normalization                           │
│     Convert NDI BGRA / UYVA -> Normalized RGBA or UYVY + Alpha         │
│                                                                        │
│  3. Retiming Boundary to Host TAI Grid                                 │
│     • NDI timestamps are remote, asynchronous, and non-deterministic    │
│     • Discard remote sender timestamp                                  │
│     • Sample host CLOCK_TAI on frame reception: $T_{\text{recv}}$      │
│     • Quantize to nearest host grid tick:                              │
│       $GrainIndex = \left\lfloor \frac{T_{\text{recv}}}{D} \right\rfloor$ │
│                                                                        │
│  4. Cadence & Gap Management                                           │
│     If CG stops sending (static graphic), hold or idle gracefully      │
└────────────────────────────────────────────────────────────────────────┘
        │
        ▼ (Zero-Copy Commits)
[ POSIX Shared Memory: /dev/shm/mxl/<flow_id>/ ]
  └── Discrete Ring Buffer: video/rgba (8 Slots Depth)

```

### 3.1. Why Remote NDI Timestamps Must Be Retimed

* NDI carries presentation timestamps generated by the sending workstation's internal clock (often unmanaged NTP or CPU cycles).

* Network transmission over TCP/UDP introduces variable latency, packet bursts, and OS scheduling jitter.

* **The Rule of Asynchronous Ingest:** Because the remote CG machine has no physical clock sync (PTP/genlock) with the production host, this worker acts as an **Ingest Retiming Boundary**.

* The worker discards the sender's internal timestamp for scheduling purposes and anchors each frame to the local host's `CLOCK_TAI` timeline upon arrival.

### 3.2. Grid Quantization Formula

Let $D$ be the nominal frame duration in nanoseconds for the broadcast facility (e.g., $16\,683\,333\text{ ns}$ for $59.94\text{ fps}$):

$$
D = \frac{1\,000 \times 10^9}{60\,000 / 1001}
$$

When a complete NDI frame is pulled from the receiver:

1. Capture arrival instant: $T_{\text{recv}} = \text{clock\_gettime}(\text{CLOCK\_TAI})$.

2. Calculate the corresponding facility grid index:
   

   $$
   GrainIndex = \left\lfloor \frac{T_{\text{recv}}}{D} \right\rfloor
   $$

3. Stamp the MXL grain metadata:

   * `sync_timestamp` = $GrainIndex \times D$

   * `creation_timestamp` = $T_{\text{recv}}$

## 4. Alpha Channel & Format Handling

Graphics feeds require alpha channel preservation so downstream compositors (like OBS or an automated switcher) can perform clean keying over camera video.

* **Preferred Ingress Format:** `NDIlib_recv_color_format_BGRX_BGRA` or `NDIlib_recv_color_format_RGBX_RGBA`.

* **MXL Storage:** Stored as `video/rgba` (32-bit unpacked RGBA, 8-bits per component) or `video/v210` with a separate ancillary/key flow. For desktop CG sources, 32-bit `RGBA` is the standard format:
  

  $$
  \text{FrameSizeInBytes} = \text{Width} \times \text{Height} \times 4
  $$

  $$
  1920 \times 1080 \times 4 = 8\,294\,400\text{ bytes} \approx 8.29\text{ MB per frame}
  $$

### 5.2. Metadata Header Values

```
typedef struct {

    uint64_t grain_duration_ns;           // 16683333

```

## 6. Implementation Loop & NDI Polling Logic

```
void NdiIngestWorker::Run() {
    NDIlib_video_frame_v2_t video_frame;

    while (running_) {
        // 1. Capture with 20ms timeout
        NDIlib_frame_type_e frame_type = NDIlib_recv_capture_v2(
            ndi_recv_instance_, 
            &video_frame, 
            nullptr, 
            nullptr, 
            20
        );

        if (frame_type == NDIlib_frame_type_video) {
            // 2. Measure local host arrival time
            struct timespec ts;
            clock_gettime(CLOCK_TAI, &ts);
            uint64_t arrival_tai = (uint64_t)ts.tv_sec * 1000000000ULL + ts.tv_nsec;

            // 3. Quantize to host TAI grid
            uint64_t grain_index = arrival_tai / GRAIN_DURATION_NS;

            // Avoid collisions if NDI bursts two frames within the same grid slot
            if (grain_index <= last_grain_index_) {
                grain_index = last_grain_index_ + 1;
            }

            uint32_t slot = grain_index % RING_BUFFER_SIZE;
            uint8_t* dest_memory = mxl_grain_slots_[slot];

            // 4. Memory copy from NDI buffer to /dev/shm
            memcpy(dest_memory, video_frame.p_data, video_frame.line_stride_in_bytes * video_frame.yres);

            // 5. Update MXL header & trigger Linux futex wake
            update_slot_header(slot, grain_index, arrival_tai);
            atomic_store_explicit(&flow_header_->head_grain_index, grain_index, memory_order_release);
            futex_wake(&flow_header_->futex_signal);

            last_grain_index_ = grain_index;

            // 6. Free NDI frame buffer
            NDIlib_recv_free_video_v2(ndi_recv_instance_, &video_frame);
        }
        else if (frame_type == NDIlib_frame_type_none) {
            // Heartbeat / Idle: remote CG may be static or paused
        }
    }
}

```

## 7. Edge Cases & Resilience

* **NDI Source Disconnect / Generator Reboot:** If the NDI source goes offline, `NDIlib_recv_capture_v2` will time out continuously. The worker must maintain the MXL flow in `/dev/shm`, writing fully transparent frames (`alpha = 0x00`) into the ring buffer at the nominal framerate to prevent downstream compositors from freezing or stalling.

* **Variable Frame Rate (VFR) Sources:** Some presentation software only emits frames when an on-screen graphic changes. The worker must detect gaps exceeding 1 frame period and repeat the last known graphic (with its existing alpha) or emit a transparent grain according to configuration.

* **Discovery Server:** In production networks spanning subnets, mDNS discovery can fail. The worker configuration must support `extra_ips` or dedicated NDI Discovery Server settings (`ndi_discovery_server = "192.168.10.10:5959"`).
